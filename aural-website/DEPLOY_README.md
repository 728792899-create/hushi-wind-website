# 部署说明（历史入口已停用）

本文件原先面向旧版官网单独部署，包含旧 Node 版本、直接覆盖构建目录和重启等步骤，已不适用于当前三端项目。旧内容可从 Git 历史查阅，不能作为当前操作指令。

当前统一使用仓库根的 [生产准入清单与待决策事项](../docs/production-readiness.md)。第 14 步仅在本地验证，未授权或执行生产部署。

- 源码、三端依赖锁、产物和 Quality 必须对应同一候选完整 SHA；当前 Nuxt 锁要求 `^22.22.3 || ^24.15.0 || >=26.0.0`，不再沿用 Node 18/20 示例。
- 获准后的发布入口是 `aural-api/scripts/safe-deploy.js`，`deploy-production.js` 委托同一入口。它会进行真实写操作，不能当作本地演练命令。
- 持久化库、上传素材、备份与维护门禁放在 release 之外；先停旧写入并创建完整恢复点，再迁移。禁止覆盖原工作树、重写已推送历史或跳过门禁直接重启。
- 备份文件存在不等于恢复成功，进程启动不等于服务就绪。参阅 [恢复演练](../docs/backup-recovery.md) 和 [服务生命周期](../docs/service-lifecycle.md)。

真实域名、管理器、业务恢复目标、品牌资料、外部存储和通知渠道的证据与授权须另行补齐，不因本地测试通过而视为上线完成。
