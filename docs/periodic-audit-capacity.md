# 周期审计与本地容量演练

## 周期核验

用户确认默认每 24 小时全量核验一次：`AUDIT_VERIFY_INTERVAL_MS=86400000`。配置必须为 1000–604800000 的整数毫秒，非法值启动失败；短周期仅用于隔离演练。服务就绪后立即检查是否到期，此后最多每分钟检查一次。最近一次已完成尝试的开始时间持久化在 `MaintenanceRun`，重启不会无条件重复已完成的尝试；上次中断的 `running` 保留为未完成证据并允许重新核验。同进程不重叠，部署暂停和停止后不再启动新任务。

开始、成功、失败分别可在「设置 → 维护记录」查看。核验失败写固定脱敏说明，并以 `audit_integrity_failed` 进入既有严重告警；默认沿用 10 分钟去重。没有新增通知渠道，本地演练通知为空。失败不自动修复或重签审计，不新增业务写入权限限制；原有追加审计失败拒绝相关业务操作的规则不变。记录或告警持久化失败仍输出固定诊断，不会把失败变成通过。维护记录的成功只代表所示快照时点，不能证明接手前历史真实性或对抗特权者全链重写、整库回滚。

周期与后台手动核验先在调用方备份目录下建立唯一私有 `.audit-check-*` 目录（0700），通过原 SQLite FIFO 在事务外 `VACUUM INTO` 捕获一致副本（0600）。只有复制阶段占业务写队列；后续以独立单连接 `query_only` 扫描该私有副本，按 500 条分页、复用原基线/链/触发器核验，并比对扫描前后文件身份与流式摘要。成功或失败都清理本次目录，不覆盖业务库、不重签历史。原 `check:audit` CLI 与启动封存/追加入口未改变，仍有其原事务预算；不要把新私有快照入口用于活动文件的任意并发写入场景。

备份与恢复中的副本审计也不占主库写队列，内容、草稿、版本及回收记录的素材引用检查以主键每批 500 行遍历。它限制同时保留的行数，不限制单条正文大小或素材文件总数，不等于恒定内存保证。

SIGINT/SIGTERM 会停止周期 timer，等待已接受的复制、核验、结果/告警持久化和临时目录清理，再断开数据库。仍采用原 `SHUTDOWN_TIMEOUT_MS=60000`，没有提高业务等待、事务超时或 Prisma 引擎线程数。超时仍按故障退出，不能承诺清理完成。

## 超过 2 GiB 的备份大小

`BackupRecord.size` 原 Prisma Int 在 2^31 字节发生转换失败。迁移 `20261013020000_backup_size_safe_integer` 改为 SQLite REAL / Prisma Float，数据库约束为非负安全整数（至 2^53−1），保持 JSON number 与字节计数契约。此范围内整数精确可表示；禁止负数、分数和超出安全整数的值。迁移复制全部旧字段并保留已删除记录留下的自增高水位，失败时事务回滚。

本步只迁移合成库；原演示库与生产库均未迁移。以后上线必须按原授权流程停旧写入、备份、迁移及生成 Prisma 客户端。旧备份中的 INTEGER 大小可由新客户端读取；元数据边界测试不代表已经完成真实 2 GiB 数据文件恢复验收。

## 可重复的本地演练

```bash
cd ~/Projects/hushi-wind-website
TOKIO_WORKER_THREADS=2 npm --prefix aural-api run drill:capacity -- \
  --scratch-root "$PWD/logs/my-capacity-run" --profile medium
```

必须显式指定本仓库 `logs/` 下的绝对 scratch 子目录及固定档位，拒绝符号链接；不加载 `.env`，不接收已有数据库路径。每次在 scratch 下创建自己的唯一目录，只生成虚构记录和实际分块写入的素材，不读取演示或生产数据库。使用 allowlist 环境和本机回环服务，通知为空。脚本是本地测量工具，不是部署入口、生产压测或 RPO/RTO 承诺。

| 档位 | 完整签名审计 | 内容历史（约 1 KiB/条） | 合成素材 |
|---|---:|---:|---:|
| empty | 0 | 0 | 0 MiB |
| medium | 10,000 | 10,000 | 16 MiB |
| large | 100,000 | 100,000 | 128 MiB |

各阶段使用独立进程测全量审计、主库一致快照、备份、完整包验证及恢复；记录墙钟、RSS、事件循环延迟、CPU、数据库/素材字节和磁盘分配。另启动真实主入口，分别在备份、恢复和周期核验在途时发 SIGTERM，验证拒绝新入口、结果持久化、退出码和临时目录/锁清理。门闩等待单列，不将人工暂停当作业务耗时；不会因演练较慢提高生产停机预算。

单次本地工具设 20 分钟安全期限、2 GiB 进程 RSS 与 8 GiB 工作目录观测上限，并检查可用磁盘。它们是测量工具的检查边界，不是操作系统硬隔离或精确瞬时峰值保证。只终止自己创建的子进程；中断或超限报告未完成。正常收尾无论成功失败都会尝试清除本次合成数据库、素材及备份包，只保留报告和诊断日志；强制终止无法保证完成清理。结果包含核心源码前后摘要，源码变化时不将该轮计为稳定实现通过。报告和日志保留在忽略目录，不提交公开仓库。

本机各档实际结果与证据见 `SECURITY_HARDENING.md` 第 13 步。60 秒内的单次正常排空不代表生产一定可用：磁盘性能、并发工作、真实大正文、更多素材、源库复制时间和外部进程写锁都影响预算。真实管理器宽限期、业务 RPO/RTO、异地不可变副本和外部可信锚点仍须单独确认与验收。
