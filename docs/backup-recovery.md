# 本地备份恢复演练

本流程验证一个已创建的备份包能否恢复到隔离副本，不覆盖业务数据库，不启动业务服务，不发送通知。演练通过只覆盖报告中的快照时点；不等于生产恢复或灾难恢复验收。

## 留存与完整恢复点

- 操作审计 `OperationLog`、`AuditLogEntry`、`AuditIntegrityState` 全量保留。自动维护仍按原规则清理访问、登录、投递等运行记录，不清理操作审计。
- 自动备份每日检查一次，默认保留 14 天，可沿用 `BACKUP_RETENTION_DAYS` 配置。清理过期备份前，必须找到至少两个数据库、素材和审计链均验证通过的完整恢复点；不足两个时全部保留。
- 一个备份包包含同名 `.db`、`.db.manifest.json` 和 `.db.assets/`。不要拆分复制，也不要手动重写摘要让损坏包变成“通过”。清单包含版本、文件摘要/大小、表计数、素材列表及审计检查点。
- 旧清单没有检查点但数据库已有有效审计链时，仍可只读核验。没有审计链的历史备份明确标记为旧格式，不能通过本流程的完整演练，也不能替代两个已验证恢复点；不会自动为旧历史重新封存签名。

## 命令行演练

仅选择获准的本地备份和本地临时目录，两个参数都必须是显式绝对路径：

```bash
cd ~/Projects/hushi-wind-website/aural-api
npm run drill:restore -- --backup /绝对路径/本地备份.db --scratch-root /绝对路径/本地演练临时目录
```

命令不加载 `.env`，没有默认生产路径，不访问网络。它先验证源包，再将数据库、清单和全部素材复制到临时目录下新建的唯一子目录，检查全表数量、素材内容和引用、审计基线/链/保护触发器。在恢复副本中追加一条虚构 `RESTORE_DRILL` 审计并再次校验，然后重新核对源包保持不变。

成功输出 JSON 报告，包含快照时间、开始/完成时间、耗时、表/素材/审计数量、续写与清理结果；失败返回非零退出码。成功或失败均清理本次唯一子目录，包括 SQLite 临时文件。预先存在的临时根目录及其中其他文件保持不变。原备份和业务库都不会被恢复副本覆盖。

## 后台演练

超级管理员在「设置 → 数据备份」创建备份并点击「演练恢复」。只读角色可查看结果，原敏感操作确认和权限边界不变。

- 创建结果与最近演练结果分开保存，创建成功不等于演练通过。
- 开始时先保存“进行中或未完成”，结束后保存最近一次通过或失败。进程中断不会继续展示之前的成功；核查后可重新演练。
- 失败也刷新页面结果，旧成功证据失效。报告不返回客户资料或本地绝对路径。旧的自由文本成功提示不会被转换为本次通过。
- 后台操作会在当前审计链追加演练开始/完成或失败记录；虚构续写记录只存在于临时副本中。

## 本地验收与上线边界

迁移 `20261013010000_backup_verification_state` 只增加备份演练状态、时间和报告字段。已有记录默认为尚未演练。部署前仍需另行授权，停止旧 API 写入并备份后，再迁移、生成 Prisma 客户端并启动新版。启动先完成审计初始化/校验，再开启备份与维护任务。

本地验收至少覆盖完整恢复、后续素材损坏、审计内容损坏、缺文件、失败路径的临时目录清理和未完成状态显示、只读越权，以及未满两个有效点时的保留行为。测试使用合成数据，数据库、素材包与详细证据留在忽略目录，不能提交到公开仓库。

本地摘要链不能抵御数据库特权者重写整链/整包或整库回滚，不能证明接手前历史真实。同盘备份也不能抵御整机或磁盘丢失。外部不可变留存、可信锚点、异地副本、业务 RPO/RTO 和生产恢复流程尚未验收，涉及外部服务、费用或业务规则时须先获得用户确认。
