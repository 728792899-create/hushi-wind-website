## 3. 最小实现与行为变化

### 3.1 页面查询

- 对素材、产品和目录三个既有读取接口加入仅内存的 15 秒查询缓存，最多 24 项，按账号、角色、权限、会话及令牌版本隔离；响应体不写入浏览器持久存储。
- 同一查询并发读取合并为一次传输。取消一个消费者不会取消其他消费者仍使用的请求；离页、切换筛选或关闭素材选择器时取消本次读取，并阻止旧响应覆盖新页面。
- 成功写入和原生 XHR 上传使列表缓存失效，同源标签页通过不含业务响应的版本通知同步失效。退出、会话改变和权限错误清除相关缓存；403 仍显示原错误，不被普通取消吞掉。
- 搜索采用防抖，局部加载不再使现有整块素材内容变淡；保留原列表和明确的加载/错误反馈。手动刷新绕过客户端已有缓存。并发修改使在途查询失效时只做有界重读，网络和权限错误不自动无限重试。
- 在同一缓存窗口内重复往返不必每次重新下载相同列表；其他账号的编辑没有推送通知，已有缓存最多在当前 15 秒窗口内继续使用，用户可手动刷新。没有承诺跨账号实时同步。

### 3.2 素材接口与重建

- 新后台显式传 `compact=1`，只省略未使用的顶层 `used` 与 `summary`，保留 `uploads`、逐素材引用、分类计数和分页信息。没有传 compact 的旧客户端继续得到完整响应。
- 库存缓存保留 30 秒有效期；同一时刻只执行一次重建，若内容变更越过当前重建则最多重试一次。旧代结果不得标为最新，持续变化时返回可恢复的 503，避免无界循环。
- 从“任意相关 HTTP 写请求结束就失效”改为“相关业务修改与审计成功、事务提交后失效”。无物理变化的校验失败不再触发全量重建。实际文件上传、隔离、恢复回滚同时使文件和库存缓存失效，避免缓存事务中间态。
- 历史引用只保留去重后的 URL 索引，不保留大快照；正常追加仅读取新增版本。数量、ID 范围、数据库文件身份变化或扫描前后不一致时重新核对；五分钟核对窗口到期后的下一次重建执行全量扫描。同数量外部原位修改仍依赖该全量核对，不能宣称任意外部修改立即可见。
- 文件扫描保留一分钟缓存，单文件元数据按 inode、大小和修改时间复用，仅变化文件重新读取图片头；文件 I/O 并发限制为 2，失败时等待已启动工作结束。未新增后台定时器。
- 管理员素材接口返回 Server-Timing，提供库存命中/重建及内容、历史、文件等分段耗时；不包含客户内容或凭证。`archives` 包含并行的 `history`，不能简单相加得出总耗时。
- **删除安全不依赖缓存**：既有删除事务仍实时检查当前内容、草稿、回收站和全部历史引用，保留审计失败回滚和引用阻止删除。

## 5. 可复现的本地性能对比

使用同一机器、同一合成种子及本机回环 HTTP，对比修前 `ed3bf66` 和当前代码；当前版使用 compact 响应。两档都是合成数据，没有复制客户数据库。当前规模档对齐数量而非真实内容、文件大小或网络条件。

| 档位 | 文件 / 产品 / 历史版本 | 单条历史正文 |
|---|---|---|
| 当前规模 | 81 / 11 / 70 | 约 1KB |
| 增长规模 | 81 / 50 / 10,000 | 8KB |

表内为完整 HTTP 响应中位数；热查询、提交后查询、拒绝后查询各 7 次，进程冷启动为 5 次交替独立启动。

| 场景 | 当前规模：前→后 | 增长规模：前→后 |
|---|---:|---:|
| 进程冷启动，首次全量构建 | 40.28→38.33ms | 595.43→653.56ms |
| 热查询 | 2.54→2.89ms | 2.75→4.34ms |
| 素材元数据成功提交后查询 | 8.16→4.22ms | 494.50→6.86ms |

| 第一页响应体 | 18,338→14,505B | 31,170→14,505B |

## 6. 发布准备与尚未完成的验收

发布适配已完成本地审查及 **18 项适配测试、28 项原 API 发布事务测试、19 项后台静态发布测试**。这些测试使用假运行时或本地文件，没有执行远端发布。

计划分两个兼容阶段执行：先仅更新 API，再更新后台静态文件。API 阶段保留既有升级锁、维护门禁、正常排空、完整备份、候选校验、current 原子切换和代码回滚，只停止/启动 `hushi-preview-api.service`。官网运行字节与原 release 保持一致，官网进程、Caddy、KingAI 均不重启或 reload，旧 release 保留。API 差异白名单只有前述三个运行时文件，依赖、schema、迁移及其他 API 变化均拒绝。

后台阶段完整备份原 dist，追加新散列资源、保留旧资源，最后原子替换入口并逐项 HTTPS 字节核验；失败只回退本次入口。两个阶段不是跨阶段原子事务：API 成功而后台失败时，兼容旧客户端的新 API 可继续配合旧后台，无需为静态阶段再次重启 API。

候选必须重新绑定本次完整提交 SHA 和现场 current、服务身份及配置散列。正式执行前须完成提交、普通推送及该 SHA 的 CI；发布后再做以下核验并补记：

1. 客户业务内容与上传素材保持，未导入本地夹具；数据库采用原 shared 路径，不迁移、不恢复旧库。
2. 官网字节/进程、KingAI 容器身份/启动时间、Caddy 身份与配置、既有健康探针保持。
3. 新后台入口和全部候选静态资源 HTTPS 字节一致；旧后台仍兼容 API。
4. 线上真实浏览器重复双页切换、滚动和只读搜索，记录请求数、耗时、Server-Timing 与数据计数。不得为验收新增、修改或删除线上素材。
5. 在相同请求和测量口径下补充线上前后对比，不能把本机毫秒数与跨境网络耗时混算。
