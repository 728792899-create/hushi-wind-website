## 客户如何替换素材和内容

1. DNS、HTTPS 与最终访问验证完成后，先通过站点门禁，再登录管理后台。
2. 在素材管理中上传客户自有或已获授权的图片、文件，使用清晰的文件名与用途说明。不要把证件、密码、客户联系方式等敏感信息当作网站素材上传。
3. 在允许编辑的文章或 CMS 栏目中选择新素材，替换对应文字与图片，保存后检查官网实际显示；手机和桌面各看一次。
4. 产品、艺术家和首页系统配置的替换需求交给管理员处理。上传新文件不会自动替换所有页面上的旧引用，也不需要先删除旧文件。
5. 管理员核对替换结果并保留可恢复备份后，再决定是否清理旧素材。临时验收账号没有删除权限。

当前产品、人物介绍、品牌历史、服务承诺和素材仍属于原演示内容，需客户逐项确认或替换。保留原素材用于受保护验收，不代表全部素材已完成商业许可核验，也不代表这些品牌宣称已经核实。正式公开范围需另行确认。

## 后续迁移必须携带什么

客户开始上传和编辑后，迁移应以**临时站的最新一致性备份**为准，不再用这次初始 49 条内容包覆盖。迁移包需要同时包括：

- 对应版本的官网、后台、API 产物及运行依赖；记录当前 commit 和文件校验值。
- 应用生成的一致性数据库备份及其 manifest，不直接拷贝正在写入的 SQLite 文件。
- 与该快照匹配的 uploads/资源备份，包含客户后来上传的文件；数据库与素材必须成套验证。
- 独立环境配置及所需密钥，包括数据库/上传路径、域名、CORS、应用签名密钥、账号初始化配置以及已有加密功能所依赖的密钥。敏感配置单独安全传输，保留正确权限，不放进公开源码包或 Git。
- 胡氏专用 systemd 启动配置、反向代理与访问门禁配置、备份任务配置及恢复说明；不得打包同机 KingAI 的配置、数据或密钥。

目标机先建立独立目录、权限和服务，再按该版本验证数据库及 uploads，设置目标域名并完成浏览器验收；确认后才切换客户入口。原临时站和完整备份保留到目标验收完成，避免客户上传期间两边同时写入。账号或密钥轮换需要与会话失效、已有加密数据兼容性一起安排，不能只换配置值后假定迁移完成。
